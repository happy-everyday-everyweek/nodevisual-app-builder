# NodeVisual App Builder Spec

## Why
当前市面上的低代码/无代码工具大多依赖云端编译、PC 端操作，无法让创作者在移动端独立完成"设计 → 编辑 → 编译 → 打包"的完整闭环。本项目旨在打造一款**完全端侧运行**的移动端（Android 优先）可视化节点编程工具：用户通过连接节点构建函数、拖拽生成 UI 界面，并一键将项目编译打包为 Web / Android / Windows 多端应用，全程不依赖云服务。

## What Changes
- 新增：节点式函数编辑器（通过连接节点形成可执行函数）
- 新增：可视化 UI 编辑器（拖拽组件生成界面）
- 新增：项目三段式结构（函数 + 数据库 + UI），通过悬浮胶囊状 Top 栏切换
- 新增：函数组织能力（命名、打标签、文件夹/子文件夹嵌套分类）
- 新增：节点系统（变量、运算、流程控制、数据库、函数调用、插件节点等）
- 新增：变量引用系统（`#` 触发卡片选择 + `#变量名` 输入式快速引用）
- 新增：插件系统（封装好的函数节点，如 LLM 调用 OpenAI / Anthropic SDK）
- 新增：多端编译打包（Web / Android / Windows），完全端侧
- 限定：作为移动端软件运行，优先兼容 Android 平台

## Impact
- 全新项目，无既有代码影响
- 关键技术选型（建议）：
  - 构建器本体：**Flutter**（移动端框架，原生 Android 兼容性强，Canvas 能力足以承载节点图渲染）
  - 节点图渲染：自绘 Canvas + 自定义 RenderObject
  - 状态管理：Riverpod / Bloc
  - 项目持久化：本地 SQLite + 文件系统
  - 编译产物目标：以 Flutter/Dart 为 IR 目标，复用其多端能力（Android APK / Web / Windows Desktop）
- 关键风险：
  - 端侧多端编译（尤其是 Windows 可执行）在移动设备上极具挑战，需嵌入式编译管线 + 预编译运行时
  - 节点图在移动端小屏上的交互需重新设计（不能照搬 PC 端节点编辑器）

## ADDED Requirements

### Requirement: 项目结构
系统 SHALL 提供三段式项目结构：**函数（Functions）/ 数据库（Database）/ UI**。每个项目独立包含这三部分。

#### Scenario: 项目切换
- **WHEN** 用户在编辑器内任意位置
- **THEN** 顶部始终悬浮一个胶囊状 Top 栏，包含"函数 / 数据库 / UI"三段切换入口
- **AND** 切换时各自编辑器状态独立保留，互不丢失
- **AND** 胶囊栏不遮挡核心编辑区域，可半透明叠加

### Requirement: 函数组织
系统 SHALL 支持对函数进行命名、打标签、放入文件夹分类，且文件夹支持无限层级子文件夹嵌套。

#### Scenario: 函数分类
- **WHEN** 用户创建或编辑函数
- **THEN** 可设置函数名称
- **AND** 可为一个函数添加多个标签
- **AND** 可将函数移动到任意层级的文件夹
- **AND** 文件夹支持子文件夹无限嵌套
- **AND** 支持按标签、名称、文件夹路径检索函数

### Requirement: 节点系统（双平面模型）
系统 SHALL 采用**控制平面 / 数据平面分离**的节点模型：

- **控制平面**（画布连线）：仅表达执行顺序与控制流分支；连线**无类型校验**
- **数据平面**（节点编辑页内的 `#` 引用）：表达数据输入与输出；用户点击节点进入节点编辑页进行配置

每个节点根据**自身配置**动态声明任意数量的**命名输出**（控制流输出与数据输出皆然）。节点提供以下基础类别：

- **变量节点**：设置变量、读取变量
- **运算节点**：算术运算（加减乘除等）、逻辑运算（与或非）、字符串运算（拼接、截取等）
- **流程控制节点**：条件分支（可配置任意数量 case，每个 case 一个控制流输出）、循环（body / completed 等命名输出）
- **数据库节点**：表的增、删、改、查，以及表结构操作
- **函数调用节点**：调用项目内其他函数
- **插件节点**：调用插件提供的封装函数（如 LLM 调用）

#### Scenario: 节点连接形成函数
- **WHEN** 用户在函数编辑器中拖拽节点到画布
- **AND** 在节点之间连接控制流线（表达执行顺序与分支去向）
- **THEN** 形成有向无环图（DAG）表示的函数控制流
- **AND** 画布连线仅承载控制流，不承载数据，不进行类型校验
- **AND** 数据输入在点击节点进入的节点编辑页内通过 `#` 引用完成

#### Scenario: 节点输出动态声明
- **WHEN** 用户配置某个节点（如为 If 节点添加多个 case、为 DB 查询节点选择输出 rows/affected）
- **THEN** 节点按配置动态声明其命名控制流输出与命名数据输出
- **AND** 这些命名输出可被下游节点的 `#` 引用

### Requirement: 变量引用
系统 SHALL 支持在节点的参数输入框中通过 `#` 触发变量引用，引用来源包括：

1. **控制流上游节点输出**：沿控制流连线反向传递闭包可达的节点的命名数据输出（循环体内声明的变量仅在循环内可见）
2. **函数变量**（函数作用域内变量）
3. **项目变量**（项目作用域内变量）

每个命名数据输出声明一个原始类型（`number / string / bool / any`，`List / Map` 在 v1 为无参容器）。当 `#` 引用类型与目标参数不匹配时，系统在**节点编辑页内**提示（不在画布上拦截）。

#### Scenario: 卡片式选择引用
- **WHEN** 用户在节点编辑页的参数输入框中输入 `#`
- **THEN** 弹出一个选择卡片，列出当前可选变量
- **AND** 卡片按来源分组（控制流上游节点输出 / 函数变量 / 项目变量）
- **AND** 每项显示其声明的类型作为提示
- **AND** 支持搜索过滤
- **AND** 选中后自动插入变量引用标记（两段式：先选节点 → 再选输出名；或直接输入 `#名称` 命中即用）

#### Scenario: 输入式快速引用
- **WHEN** 用户在参数输入框中输入 `#变量名`
- **THEN** 系统匹配对应变量并建立引用
- **AND** 若变量名跨来源不唯一或不存在，列出全部候选项并标注来源，由用户选择

### Requirement: 可视化 UI 编辑器
系统 SHALL 提供拖拽式 UI 编辑器，用户可在画布上放置、调整 UI 组件并配置属性，生成的 UI 与函数节点数据绑定。

#### Scenario: 拖拽生成界面
- **WHEN** 用户切换到"UI"段
- **THEN** 显示 UI 组件面板与画布
- **AND** 用户可从面板拖拽组件到画布
- **AND** 可调整组件位置、尺寸、属性
- **AND** 可将组件属性绑定到函数命名输出或项目变量（通过 `#` 引用）

#### Scenario: 组件事件触发函数
- **WHEN** 用户在 UI 编辑器中点击某组件
- **THEN** 显示该组件支持的所有触发点（如按钮点击、列表项滚动到此处、组件加载、组件卸载等）
- **AND** 可将触发点绑定到某函数（执行该函数）

### Requirement: 函数触发模型
系统 SHALL 支持函数被以下方式触发执行，函数声明其入口点（entry），自身不关心触发来源：

- **组件生命周期事件**：列表项滚动到此处、组件加载、组件卸载等
- **组件交互事件**：按钮点击、输入框提交等
- **定时器**
- **外部事件**：推送、深度链接等
- **另一个函数的"函数调用"节点**

#### Scenario: 函数作为入口被触发
- **WHEN** 绑定的触发条件满足（如用户点击按钮、定时器到期、列表项进入视口）
- **THEN** 系统执行对应函数的控制流图
- **AND** 函数执行过程中的命名数据输出登记进可见作用域，供下游 `#` 引用
- **AND** UI 组件可通过 `#` 引用函数命名输出以更新显示

### Requirement: 插件系统
系统 SHALL 提供插件机制，将常用能力封装为可复用的函数节点：

- **内置插件**：LLM 调用插件，封装 OpenAI SDK 与 Anthropic SDK 的常用调用能力（对话补全、消息、流式输出等）
- **插件能力**：每个插件节点声明其输入参数、输出、所需配置（如 API Key）
- **扩展性**：支持后续接入第三方插件

#### Scenario: 使用 LLM 插件
- **WHEN** 用户在函数中添加 LLM 节点
- **AND** 配置模型提供商（OpenAI / Anthropic）、模型、API Key
- **AND** 连接输入（prompt 来源）与输出（结果去向）
- **THEN** 函数执行时调用对应 SDK 完成请求并返回结果

### Requirement: 多端编译打包
系统 SHALL 支持一键将项目编译打包为以下产物，且编译过程**完全在端侧完成，不依赖任何云服务**：

- **Web 应用**：可部署的 HTML/JS 静态包
- **Android 应用**：可安装的 APK
- **Windows 应用**：可执行文件（.exe 或可运行目录）

#### Scenario: 一键多端编译
- **WHEN** 用户在项目中点击"编译打包"
- **THEN** 选择目标平台（可多选）
- **AND** 系统在端侧完成代码生成、编译、打包
- **AND** 完成后输出对应产物到本地，并提供导出/分享

### Requirement: Android 平台优先兼容
系统 SHALL 作为移动端软件运行，UI 与交互针对移动端小屏设计，优先保证 Android 平台兼容性。

#### Scenario: Android 兼容
- **WHEN** 应用运行于 Android 设备
- **THEN** 节点编辑、UI 编辑、编译打包等所有核心功能在 Android 上可用
- **AND** 交互针对触屏优化（如节点拖拽、画布平移缩放、变量卡片选择等）
- **AND** 适配不同 Android 屏幕尺寸与方向

## Technical Notes (技术说明，非强制约束)

### 架构 Spike 锁定决策

以下决策经 brainstorming 对齐后锁定，作为实现的权威依据：

1. **双平面模型**：画布连线（控制平面）只表达执行顺序与控制流分支；数据引用（数据平面）在节点编辑页内通过 `#` 完成。画布**无数据端口、无类型校验、无扇出节点**。
2. **执行模型**：IR 即运行时格式，Dart 节点解释器按控制流图遍历执行。每执行一个节点，将其命名数据输出登记进可见作用域。预览与正式运行同源解释器。代码生成降级为 P8 可选优化，无需改 IR。
3. **节点输出动态化**：节点根据自身配置动态声明任意数量的命名输出（控制流输出 + 数据输出皆然）。如 If 节点可配置任意数量 case，每个 case 一个控制流输出；DB 查询可同时声明 `rows` 与 `affected` 数据输出。
4. **类型在输出值层**：每个命名数据输出声明原始类型（`number / string / bool / any`，`List / Map` 在 v1 为无参容器）。类型校验在节点编辑页内提示，不在画布拦截。泛型与用户自定义类型留后续。
5. **`#` 作用域**：控制流上游（沿控制连线反向传递闭包）+ 函数变量 + 项目变量。循环体内变量仅循环内可见。名称跨来源冲突时列候选并标注来源。
6. **函数触发模型**：函数声明 entry，不关心触发来源。支持组件生命周期/交互事件、定时器、外部事件、另一函数的函数调用节点。
7. **UI 绑定**：组件事件 → 触发函数；组件属性 → `#` 引用函数命名输出或项目变量。与节点编辑页内 `#` 同源机制。

### IR Schema（JSON，权威格式）

```
project: { meta, projectVars[], functions[], db{tables[]}, ui{tree} }
function: { id, name, tags[], folderId, entry?, nodes[], controlEdges[] }
node:     { id, kind, params{}, position{x,y},
            controlOutputs[],    // 节点自声明的命名控制流输出
            dataOutputs[] }      // 节点自声明的命名数据输出（每项含 name + type）
param 内的 # 引用: { ref: { source: upstream|funcVar|projVar,
                           nodeId?, outputName?, varId? } }
controlEdge: { fromNode, fromPort, toNode }   // 控制流边，无类型
entry: { kind: uiEvent|timer|external|funcCall, ref }   // 函数入口
```

### 插件协议

插件声明：`inputs[]`（命名+类型）/ `outputs[]`（命名+类型）/ `configSchema`（如 API Key）/ Dart `executor`。LLM 内置插件按此协议实现 OpenAI / Anthropic executor，第三方插件后续按同协议接入。

### 存储与安全

- 项目 = 文件夹：`project.json` + `functions/*.json` + `db.json` + `ui.json`
- 运行时数据（应用本身的 DB）= SQLite
- API Key 等敏感配置 = Android Keystore 安全存储

### 端侧多端编译

- 解释器模型使 Windows 可行性大增：只需把「解释器 + IR JSON」打包成可运行包
- v1 优先级：**Web + Android 先通**，Windows 列后续里程碑
- 代码生成作为发布构建的可选优化路径，需保证与解释器语义一致

### 移动端交互

- 节点图移动端交互：参考"捏合缩放 + 双指平移 + 长按拖拽节点"，避免照搬桌面端右键菜单
- 变量卡片：在移动端以底部 Sheet 或悬浮卡形式呈现，便于单手操作
- 控制流连线在移动端用粗线 + 大命中区，便于触屏拖拽
